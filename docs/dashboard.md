- **담당 자리 3단계**: 지시 실행 중 = 파란 빛·'작업 중…'(그대로) → 지시가 끝나면(`status: done`) 그 지시에서 일한 자리(`o.worked` = 비서실장 + 실행 중 `active`에 한 번이라도 잡힌 담당)가 **녹색 테두리 + 녹색 이름표 '✔ 작업 완료'** → 배포할 가게가 있는 지시(`배포준비:`)는 **배포 완료**(`deployState: done`)되면, 배포 없는 지시는 **캡틴이 결재함(또는 업무 기록)에서 그 지시를 열어 보면** 사라진다. 열어 봄은 `POST /api/order/seen` → 지시 파일 `seenAt`에 남아 폰·PC가 같다. 같은 지시를 '답하기'로 다시 돌리면 끝날 때 `seenAt`이 지워져 다시 녹색이 된다. 실패·멈춤 지시는 녹색을 안 띄운다. `worked`가 없는 옛 지시(2026-10-30 전)는 표시 안 함.
- '작업 중…'·'✔ 작업 완료'는 말풍선으로 띄우면 위쪽 부서 간판·옆 사람 말풍선과 겹쳐서 **이름표 아래 줄**(맡은 일 자리)에 쓴다(작업 중 = 파란 이름표, 완료 = 녹색 이름표). 예전 '작업 중…' 말풍선은 같은 날 사용자 승인으로 없앴다. 폰은 이름표가 한 줄 높아져서 오른쪽 사람 이름표를 아래로 붙인다.
- **인력 공급팀 보고**: `/api/hr`의 `report` = 오늘(베트남 날짜) `daily_entries`에 `shift=day`/`night` 줄이 하나라도 있는지. 자리 오른쪽에 '주간 보고 완료 ✔'·'야간 보고 완료 ✔'(녹색), 베트남 시간 9시가 지나도 주간이 없으면 빨간 '주간 보고 없음', 21시가 지나도 야간이 없으면 빨간 '야간 보고 없음'. 인력 앱 연결 안 됨·`daily_entries`를 못 읽음이면 아무것도 안 보인다. 2분 캐시라 입력 후 최대 2분 늦게 바뀐다.

## 비밀값(환경변수) 읽는 방식 (2026-10-30)
- **증상**: 사용자가 `QRMENU_ADMIN_KEY`를 넣었는데 방문 기록이 '연결 필요'. 키는 윈도우 사용자 환경변수에 제대로 있었다. 서버는 켜질 때의 환경만 읽는데, 그 서버를 켠 탐색기가 옛 환경을 갖고 있었다(바로 앞에 AI가 `explorer.exe start-dashboard.bat`으로 재시작함).
- **고침(구조)**: `server.py`의 `user_env()`가 `QRMENU_ADMIN_KEY`·`VERCEL_TOKEN`·`JINWOO_HR_*`를 **쓸 때마다 레지스트리(HKCU\Environment)에서 직접** 읽는다. 이제 비밀값을 넣거나 바꾸면 대시보드를 다시 켜지 않아도 된다(방문 기록은 5분, 인력 앱은 2분 캐시 뒤 반영).
- **같이 고침**: 지시 실행(`claude -p`)에 서버 환경을 그대로 넘기면서 이 비밀값들(Vercel 토큰·인력 앱 계정)도 AI 실행 환경에 들어가 있었다. 이제 `SECRET_ENV`는 빼고 넘긴다. AI가 그 값을 읽거나 쓴 기록이 있는지는 확인하지 않았다.
- 확인: 재시작 뒤 방문 기록 '최근 30일' 87곳 표가 보임(PC 1920), 인력 앱 ok, Vercel 토큰 있음.
