# 구글 지도 사진 수집기

> 이 파일은 CLAUDE.md에서 옮겨 온 상세 기록이다(2026-10-23, 사용량 절약). 필요할 때만 읽는다.

## 구글 지도 사진 수집기 (`tools/maps-photos/`, 2026-10-23)
- 사용자 PC에서 돌리는 대시보드형 수집기(이 클라우드 환경은 구글 지도 접속이 막혀 있어 여기서는 못 돌림). 제미나이로 만든 터미널용 `google_maps_photo_fetcher.py`를 대신한다(같은 사진이 메뉴판·음식·매장 폴더에 겹쳐 저장, '사진 추가' 버튼을 잘못 누를 수 있음, 탭 구분 없이 화면 전체를 긁음 → 다시 만듦).
- **사용자 쪽**: `qrmenu_photos.py`와 `run_dashboard.bat`을 한 폴더에 두고 bat 더블클릭(처음에 playwright·pillow 설치, PC 크롬 사용) → 브라우저 `http://127.0.0.1:8765` 대시보드. 가게 이름이나 구글 지도 링크 입력 → 수집(가게 정보 + 갤러리 탭 전체·최신·메뉴·음식·가게 제공·분위기) → 사진을 메뉴판/음식/매장/기타/제외로 고름(크게 보기에서 키보드 1~5) → "드라이브에 저장" → 대시보드가 세션에 보낼 문장을 만들어 줌. 로봇 확인이 뜨면 열린 크롬 창에서 직접 체크(크롬 프로필 `~/.qrmenu_photos/chrome-profile`에 기억됨).
- **저장 결과**(`내 드라이브/QR메뉴판/<가게>/`): `menu_NN.jpg`·`food_NN.jpg`·`store_NN.jpg`·`etc_NN.jpg`(1600px), `store_info.json`(가게 정보·사진별 분류·보인 탭·`owner`=가게 계정이 올림·`latest_rank`=최신 탭 순서), `클로드_안내.md`, **`claude_bundle_N.zip`**(사진+store_info.json, 8MB 이하로 나눔 — 드라이브 도구 10MB 제한).
- **세션 쪽**: 드라이브에서 `claude_bundle_*.zip`을 찾아 `download_file_content`로 받기 → 결과가 저장된 `tool-results/…txt` 경로를 `python3 -I tools/maps-photos/unpack.py <스크래치폴더>/<가게> <경로…>`에 넘기면 풀고 가게 정보·분류별 장수·가게 계정 사진·최신 순서를 출력한다. 빠진 묶음이 있으면 알려 준다. 그다음 finder에게 `menu_*.jpg` 판독을 맡긴다.
- **한계**: 사진을 올린 날짜·올린 사람 이름은 수집하지 않는다(가게 계정 여부와 최신 순서만). 메뉴판이 몇 개월 전 것인지 기록할 때는 "최신 탭 N번째" 또는 사용자 확인으로 대신한다. 구글 지도 화면 구조(클래스 이름)가 바뀌면 갤러리를 못 열 수 있다 → 그때는 가게 화면에 보이는 사진만 모으고 기록에 남긴다. 사용자가 오류 화면이나 '기록 보기' 내용을 보내 주면 고친다.
- **첫 실제 사용(2026-10-23, 청식당 54 Lý Nhân Tông, v1.1)**: 가게 정보는 다 읽었지만 사진 갤러리를 못 열어(`gallery_tabs: []`) 첫 화면 사진 9장만 '기타'로 모임. 사진 주소는 `lh3.googleusercontent.com/grass-cs/…` 형태. → **v1.2**: 가게 화면의 '메뉴' 탭을 눌러 '메뉴' 칸=메뉴판·'하이라이트' 칸=음식으로 나눠 읽고, 메뉴 칸 첫 사진을 크게 열어 → 키로 넘기며 큰 사진을 받음(갤러리 구조에 덜 의존). 갤러리가 안 열리면 맨 위 사진을 크게 열어 같은 방식. 단계마다 **진단 캡처 `debug_NN_<단계>.jpg`**(첫 묶음 zip·드라이브 폴더)와 `store_info.json`의 `debug`(보이는 탭·제목·사진 버튼·`a[data-photo-index]` 수)를 남김 → 수집이 이상하면 이것부터 보고 고친다.
- **v1.2도 실패 → 진단 캡처로 원인 확인(2026-10-23)**: 수집용 크롬(프로필 `~/.qrmenu_photos/chrome-profile`)이 **구글에 로그인돼 있지 않으면 지도가 줄인 화면을 보여 줘 탭이 '개요·리뷰'뿐이고 '메뉴' 탭이 없다**(사용자 평소 크롬은 로그인돼 메뉴 탭이 보임). 맨 위 큰 사진 버튼 이름은 '<가게> 사진'(예: '청식당 사진', '의' 없음), 리뷰어 얼굴은 '<사람> 사진', 리뷰 사진은 '…님의 리뷰에 포함된 N번째 사진'. → **v1.3**: 대시보드 '구글 로그인' 버튼(수집용 프로필로 **자동 조종 아닌 일반 크롬**을 열어 로그인 — 자동 조종 크롬은 구글이 로그인을 막을 수 있음, 한 번 하면 기억), 로그인 안 됐으면 경고, 큰 사진 버튼을 '<가게> 사진'으로 정확히 찾아 사진 목록 또는 크게 보기로 수집.
- **v1.4(2026-10-23)**: 로그인용 크롬 창을 열어 둔 채 수집하면 같은 프로필을 그 창이 쥐고 있어 수집용 크롬이 바로 닫힘(`launch_persistent_context: … has been closed`, about:blank 탭만 늘어남). → 로그인 창이 열려 있으면 수집을 막고 "로그인용 크롬 창을 닫아 주세요" 안내, 오류 문구는 한 줄로 줄임.
- **v1.5(2026-10-23)**: 로그인 창을 닫아도 크롬이 백그라운드에 남아 수집용 프로필을 계속 쥐고 있어 v1.4 안내가 계속 뜸 → 프로필이 쓰이는 중이면 **수집용 프로필(`--user-data-dir=…\.qrmenu_photos\chrome-profile`)을 쓰는 chrome.exe·msedge.exe만** 찾아 끄고(PowerShell `Get-CimInstance Win32_Process`, 평소 크롬은 그대로) 한 번 다시 연다. 리눅스·맥은 `ps`로 이름에 chrom/msedge가 든 것만(처음 넣은 `pkill -f`는 경로가 든 아무 프로그램이나 꺼서 바꿈). 윈도우 명령은 이 환경에서 실행해 보지 못함.
- **첫 성공(2026-10-23, v1.5, 구글 로그인 후)**: 청식당에서 메뉴판 11장(`menu_01~11`, 메뉴책 쪽·벽 메뉴판, 1200×1600)·음식 약 24장 수집, 분류도 맞음. 드라이브 데스크톱이 사진을 먼저 올리고 `claude_bundle_*.zip`은 늦게 올라와서, 저장 직후엔 예전 zip이 받아질 수 있음(크기가 이전과 같으면 아직 동기화 중) → 그때는 `menu_*.jpg`를 하나씩 받거나 몇 분 뒤 다시 받는다.
- **시험(2026-10-23)**: 지도 접속·사진 받기만 가짜로 바꿔 대시보드 전체(수집→분류→저장→묶음 나누기→unpack)를 돌림, 갤러리 읽기 코드는 늦게 뜨는 썸네일 70장 흉내 페이지에서 70/70. 실제 구글 지도에서는 v1.5로 청식당 성공(위).
